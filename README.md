# p2anut

영어 위키백과 코퍼스로 키보드 알파벳 배열(a–z)을 최적화하는 Rust 프로그램입니다. 열 스태거 분리형 키보드(Atreus 등)의 3×10 배열을 대상으로 합니다.

> 이 프로젝트는 [Claude](https://claude.ai)(Anthropic)의 도움을 받아 만들었습니다. 코드 작성, 점수 모델 설계, 분석의 상당 부분을 Claude Code와 함께 진행했습니다.

## 동작 방식

1. **코퍼스 분석 (`analyze`)**: 영어 위키백과 덤프(`.xml.bz2`)를 받거나 스트리밍해서 글자, 바이그램, 트라이그램 빈도를 셉니다.
   - a–z와, 글자 사이의 공백 하나를 셉니다. 공백은 엄지 키라 배치 대상은 아니지만, 단어 경계를 넘는 관계를 보려고 `_`로 함께 셉니다. 예를 들어 `the end`는 `the`, `he_`, `e_e`, `_en`, `end`가 됩니다.
   - 문장부호, 숫자, 줄바꿈, 연속 공백에서 연속이 끊기고, 그 옆의 공백은 세지 않습니다(`. The`의 공백, `a  b`의 공백). 공백 두 칸은 대개 마크업이 지워진 자리입니다.
   - 같은 글자 연속(`ll`)은 바이그램으로 세지 않고, 그 쌍이 낀 트라이그램도 세지 않습니다.
   - 지금 점수 계산은 글자끼리의 n-gram만 씁니다. 공백이 낀 n-gram은 다음 단계(공백까지 포함한 트라이그램 분류)에서 씁니다.
   - 본문 문서만 씁니다. 넘겨주기, 목록 문서(`List of ...`), 동음이의·집합 색인 문서는 뺍니다.
   - 위키 마크업, 수식, 코드, 각주, 문서 끝의 참고문헌·외부 링크 섹션을 지우고 본문 문장만 셉니다.
   - 멀티스트림 덤프를 받아 두면 여러 스레드로 나눠 분석합니다. 덩어리마다 중간 결과를 `<corpus_file>.partial`에 저장하므로, 중단해도 다시 실행하면 이어서 분석합니다.
2. **최적화 (`optimize`)**: 담금질(SA)과 유전 알고리즘(GA)으로 배열을 탐색합니다.
   - 여러 엘리트 배열을 따로 탐색합니다. 엘리트끼리는 홈행 글자가 일정 개수 이상 달라야 합니다.
3. **점수**: 아래 네 항목을 모두 "검지 홈 행 키를 한 번 누르는 힘 = 1" 단위의 비용으로 바꿔 그대로 더한 값입니다. 총점은 글자당 비용의 음수라 클수록 좋고, 결과에는 글자 100개당 항목별 비용(`cost per 100 letters`)이 나옵니다.
   - 기준값은 `[costs]`에서 대표 사건 하나의 비용으로 정합니다: SFB(검지 홈 → 윗줄), 나쁜 방향 풀 시저스(중지 아랫줄 → 검지 윗줄), 안쪽 롤(중지 홈 → 검지 홈). 나머지 사건은 `[weights]`의 세부 배율로 정해집니다.
   - **effort**: 키마다 정한 노력값입니다. 행과 가운데 열에 페널티가 붙습니다.
   - **sfb**: 같은 손가락으로 연속해서 치는 경우(SFB)와, 사이에 한 글자를 두고 같은 손가락으로 치는 경우(스킵그램)의 페널티입니다. 스킵그램은 `[weights]`의 `sfs` 배율(기본 설정 0.5, 없으면 1 = SFB와 같은 무게)을 곱합니다. `ere`처럼 1·3번이 같은 글자인 같은 키 스킵그램은 어느 배열에서나 같은 키라 피할 수 없으므로 `sfs_same_key`(기본 설정 0)로 따로 정합니다. 같은 글자 연속(`ll`)은 SFB로 세지 않습니다. 배율 1일 때 실제 코퍼스에서는 이 항목의 약 3/4이 스킵그램에서 나옵니다.
   - **rolling**: 같은 손 안에서 바깥에서 안쪽으로 굴러가는 롤에 주는 보너스입니다. 바깥으로 굴러가는 롤은 `outroll` 배율을 곱합니다. 같은 손 세 글자가 방향을 꺾는 리다이렉트는 하나의 사건으로 쳐서, 안의 두 쌍은 롤로 치지 않고 `[costs]`의 `redirect` 비용만 매깁니다. 검지가 없는 리다이렉트는 `bad_redirect` 배율을 곱합니다.
   - **scissors**: 인접한 손가락이 서로 다른 행을 칠 때의 페널티입니다.
     - 풀 시저스는 두 줄 차이, 나쁜 방향 하프 시저스는 한 줄 차이에서 긴 손가락이 아래로 가는 경우입니다.
     - 스킵 시저스는 1번과 3번 글자가 시저스를 이루는 경우입니다.

## 사용법

```bash
cargo run --release -- <result_path> analyze     # 코퍼스 분석 → <result_path>/corpus.bin
cargo run --release -- <result_path> optimize    # 최적화 → <result_path>/result.bin
cargo run --release -- <result_path> run         # analyze + optimize
cargo run --release -- <result_path> results     # 저장된 결과 출력
cargo run --release -- <result_path> score mine.txt   # 내 배열을 저장된 결과 1등과 같은 기준으로 채점
cargo run --release -- <result_path> sensitivity mine.txt   # 점수 설정값에 결과가 얼마나 민감한지 점검
```

- `score`의 배열 파일은 행마다 10칸(빈칸은 `.`)씩 3행입니다. `results` 출력 형식도 그대로 읽습니다. 점수와 함께 행별 사용률, SFB·스킵그램·롤·시저스·리다이렉트 비율을 보여 줍니다.
- `sensitivity`는 점수 설정값을 하나씩 ±10/20/35/50% 흔들어, 결과가 그 값에 얼마나 기대는지 봅니다. 설정 파일과 결과 파일은 바꾸지 않습니다.
  - 흔드는 값: `[costs]` 5개, `[weights]` 10개(`row`는 SFB·시저스의 행 배율만, `roll_row`는 롤의 행 배율만), `hand_penalty`, 노력값 묶음 5개(새끼·약지·가운데 열·윗줄·아랫줄).
  - 노력값 묶음은 기준 칸보다 큰 부분만 흔듭니다. 열 묶음은 같은 행 검지 대비, 행 묶음은 같은 열 홈 대비입니다.
  - 후보는 저장된 결과 전부와 명령줄에 준 배열 파일입니다. 같은 배열이나 좌우를 뒤집은 배열은 하나만 남깁니다. 지금 설정에서 1등인 후보가 기준입니다.
  - 칸마다 두 가지를 봅니다. 다른 후보가 1등이 되면 `R`, 바뀐 설정으로 기준 1등에서 근처 탐색(두 키 맞바꾸기·세 키 돌리기를 더 좋아지지 않을 때까지, 무작위 없음)을 했을 때 움직이는 키 수는 숫자입니다. `.`은 변화 없음입니다.
  - 방향마다 처음 바뀌는 폭과 그때의 배열을 보여 주고, 끝에 민감(±20% 안에서 바뀜)·중간(±35–50%)·둔감(±50%까지 그대로)으로 묶습니다.
  - 근처 탐색만 하므로, 전혀 다른 배열이 1등이 되는 경우는 잡지 못합니다. 민감하게 나온 값은 바꿔서 `optimize`를 다시 돌려 보세요.
- `--reset`을 붙이면 기존 결과를 무시하고 새로 시작합니다. 분석 중간 저장(`.partial`)은 덤프·파서·표본 비율이 같으면 `--reset`이어도 이어서 씁니다. 처음부터 다시 하려면 그 파일을 지우세요.
- 예전 버전이 만든 `corpus.bin`은 형식이 달라 읽지 못합니다. `analyze --reset`으로 다시 만드세요. 공백을 세기 전의 코퍼스(파서 v3)는 읽히지만 경고가 나오고 공백 n-gram이 없습니다.
- Ctrl-C를 한 번 누르면 이번 라운드가 끝난 뒤 저장하고 종료합니다. 두 번 누르면 바로 종료합니다.

## 설정 (`config.toml`)

| 항목 | 설명 |
|---|---|
| `wikipedia_dump_url` | 덤프 주소입니다. 문자열 하나나 목록(공식·미러)으로 적습니다. 목록이면 받기 전에 각 주소에서 앞부분 4MiB를 받아 속도를 재고 빠른 곳부터 씁니다. 속도는 첫 데이터가 도착한 뒤부터 재서, 멀리 있는 미러의 연결 지연이 섞이지 않습니다. 응답이 없거나 파일 크기가 다른 주소는 빠지고, 받다가 계속 실패하면 다음 주소로 넘어가 이어받습니다. 모든 주소는 파일 이름이 같아야 합니다. 병렬 분석과 이어서 분석을 하려면 `*-pages-articles-multistream.xml.bz2`를 쓰세요. |
| `wikipedia_download`, `wikipedia_dump_file` | `wikipedia_download = true`면 덤프를 `result_path` 아래에 먼저 받아 두고, 끊겨도 이어받습니다. 파일 이름은 URL의 마지막 부분입니다. 이름을 직접 정하려면 `wikipedia_dump_file`을 쓰세요. 둘 다 없으면 스트리밍으로 한 스레드에서 분석합니다. 전체 덤프는 약 27GB입니다. |
| `wikipedia_verify` | 다 받은 덤프를 Wikimedia가 공개하는 SHA-1(`<wiki>-<날짜>-sha1sums.txt`)과 비교합니다(기본 켜짐). 체크섬은 공식 주소에서 먼저 구합니다. 다르면 파일을 `<이름>.bad`로 옮기고 멈추며, 체크섬 파일을 못 구하면 경고만 하고 진행합니다. |
| `wikipedia_sample` | 문서 표본 비율입니다(0 초과 1 이하). 제목 해시로 덤프 전체에서 고르게 뽑습니다. |
| `wikipedia_limit` | 덤프 앞쪽 N개 문서만 분석합니다(0 = 전체). 오래된 문서 위주라 편향되므로 빠른 확인용입니다. |
| `bigram_coverage`, `trigram_coverage` | 최적화에 쓸 빅그램·트라이그램의 누적 빈도 비율입니다(기본 0.99, 0.97). 글자끼리의 것과 공백이 낀 것에 따로 적용해서, 공백 n-gram이 늘어도 글자끼리 남는 것은 그대로입니다. 코퍼스 파일에는 전체 통계를 저장하므로, 바꿔도 다시 분석할 필요가 없습니다. |
| `elites`, `min_home_diff` | 엘리트 배열 수와, 엘리트끼리 홈행 글자가 최소 몇 개 달라야 하는지입니다. |
| `min_hand_usage`, `hand_penalty`, `hand_hard_limit` | 손 비율 제약입니다. 덜 치는 손이 `min_hand_usage` 이상이면 감점이 없고, 모자라면 글자 100개당 `hand_penalty × (모자란 %p)²`를 감점합니다. `hand_hard_limit` 아래는 실격입니다(지정하지 않으면 `min_hand_usage`와 같아서 기준 아래는 바로 실격). |
| `center_rare` | 빈도가 가장 낮은 n글자를 가운데 두 열에 강제로 배치합니다(0 = 끔, 2–6). |
| `seed` | 난수 시드입니다. 비워 두면 실행할 때마다 출력되는 값을 넣어 같은 실행을 재현할 수 있습니다. |
| `[weights]` | 행·간격·가운데 열 페널티, 롤 방향, 시저스 종류별 배율입니다. |
| `[effort]` | 키마다의 노력값입니다(검지 홈 = 1.0). 왼손 새끼부터 가운데 열까지 행마다 5칸이고 오른손은 좌우 대칭입니다. 쓰시는 키보드에 맞게 바꿀 수 있고, 바꿔도 `[costs]`의 대표 사건 비용은 그대로 유지됩니다. |
| `[costs]` | 총점의 기준값입니다. 대표 사건(SFB, 나쁜 방향 풀 시저스, 안쪽 롤, 리다이렉트) 한 번이 검지 홈 행 키 몇 번을 누르는 만큼인지와 노력값 배율을 정합니다. 예전 설정의 `score_normalization`, `[rates]`는 무시됩니다. |
| `[sa]`, `[ga]` | 담금질과 유전 알고리즘의 탐색 파라미터입니다. |

## 테스트

```bash
cargo test
```

### 덤프 파싱 확인 (`test_dump`)

```bash
cargo run --release --bin test_dump -- <result_path> [articles]   # 기본 2000, 0이면 첫 문서만
```

- 첫 본문 문서의 원문과 정리된 결과를 보여 줍니다.
- 앞쪽 `articles`개 문서를 정리해서 아래 내용을 출력합니다.
  - 많이 나온 단어 상위 60개
  - 마크업 찌꺼기로 의심되는 토큰(`nbsp`, `frac`, `jpg`, `http` 등)의 100만 단어당 빈도
  - 끝 섹션(References, See also 등)을 잘라 낸 문서의 비율
- 의심 토큰 가운데 `times`, `minus`처럼 원래 영어 단어인 것은 절대값보다 수정 전후 비교에 쓰세요.
