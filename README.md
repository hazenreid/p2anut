# p2anut

영어 위키백과 코퍼스로 키보드 알파벳 배열(a–z, 설정에 따라 스페이스까지)을 최적화하는 Rust 프로그램입니다. 열 스태거 분리형 키보드(Atreus 등)의 3×10 배열을 대상으로 합니다.

> 이 프로젝트는 [Claude](https://claude.ai)(Anthropic)의 도움을 받아 만들었습니다. 코드 작성, 점수 모델 설계, 분석의 상당 부분을 Claude Code와 함께 진행했습니다.

## 동작 방식

1. **코퍼스 분석 (`analyze`)**: 영어 위키백과 덤프(`.xml.bz2`)를 받거나 스트리밍해서 글자, 바이그램, 트라이그램 빈도를 셉니다.
   - a–z와 공백을 셉니다. 공백은 `_`로 표시합니다. 예를 들어 `the end`는 `the`, `he_`, `e_e`, `_en`, `end`가 됩니다.
   - 공백은 양옆이 글자이거나 실제 글의 문장부호·숫자(`. , ; : ! ? ( ) [ ] " '`와 숫자)일 때 누름 1번으로 셉니다. 줄 처음·끝과, 마크업 찌꺼기 같은 그 밖의 기호 옆 공백은 세지 않습니다. 연속 공백은 대개 마크업이 지워진 자리라 누름 1번으로만 치고 양옆과 잇지 않습니다.
   - n-gram은 배열에 있는 키끼리만 잇습니다. 문장부호·숫자는 n-gram에 넣지 않고 연속을 끊으며, 그 옆의 공백 하나는 글자 쪽과만 이어 셉니다(`. The` → `_t`, `_th`, `end.` 앞의 공백은 `d_`).
   - 분석이 끝나면 공백을 경우별(글자 사이, 문장부호·숫자 옆, 문장부호·숫자끼리, 연속 공백, 세지 않음)로 몇 번 셌는지 보여 줍니다.
   - 같은 글자 연속(`ll`)은 바이그램으로 세지 않고, 그 쌍이 낀 트라이그램도 세지 않습니다.
   - 스페이스를 엄지에 둘 때(`space_key = "thumb"`, 기본) 점수 계산에서 공백이 낀 n-gram은 `글자 _ 글자` 창(공백 너머 스킵그램·스킵 시저스)에만 씁니다. 이 창은 양옆이 글자인 공백만 세므로 문장부호 옆 공백 규칙과 상관없습니다.
   - 스페이스를 배열에 둘 때(`space_key = "grid"`)는 공백을 27번째 키로 보고, 공백이 낀 n-gram을 글자끼리의 것과 똑같이 SFB·시저스·롤·리다이렉트에 씁니다.
   - 엄지 방식의 롤은 글자끼리의 바이그램·트라이그램으로 계산하며, 공백까지 넣어 세 키 창으로 나눠 세는 방식과 값이 같습니다(같은 손 두 글자는 창 두 개에 들어가므로). 창 방식은 문장부호 옆 단어의 롤을 덜 세게 되므로 쓰지 않습니다.
   - 본문 문서만 씁니다. 넘겨주기, 목록 문서(`List of ...`), 동음이의·집합 색인 문서는 뺍니다.
   - 위키 마크업, 수식, 코드, 각주, 문서 끝의 참고문헌·외부 링크 섹션을 지우고 본문 문장만 셉니다.
   - 멀티스트림 덤프를 받아 두면 여러 스레드로 나눠 분석합니다. 덩어리마다 중간 결과를 `<corpus_file>.partial`에 저장하므로, 중단해도 다시 실행하면 이어서 분석합니다.
2. **최적화 (`optimize`)**: 무작위 배열에서 시작하는 담금질(SA)을 여러 번 돌려 가장 좋은 배열을 찾습니다.
   - 담금질을 `starts_per_batch`(기본 40)개씩 묶어 동시에 돌리고, 같은 최고점이 `stop_after_hits`(기본 3)번 나오면 멈춥니다. 최소 한 묶음, 최대 `max_starts`(기본 2000)번입니다. 결과에 "최고점이 몇 번 중 몇 번 나왔는지"를 보여 주므로, 한 번만 나온 최고점이면 더 찾아볼 여지가 있다는 뜻입니다.
   - 여러 엘리트 배열을 차례로 찾습니다. 엘리트끼리는 홈행 글자가 일정 개수 이상 달라야 합니다. 저장된 결과가 있으면(`--reset` 없이) 엘리트마다 그 배열을 첫 시작점으로 써서 이전보다 나빠지지 않습니다.
   - 예전의 유전 알고리즘과 두 번째 라운드는 실행 기록상 결과를 바꾼 적이 없어서(최고점은 모두 첫 40번 안에 나옴) 뺐습니다.
3. **점수**: 아래 네 항목과 손 비율 감점을 모두 "검지 홈 행 키를 한 번 누르는 힘 = 1" 단위의 비용으로 바꿔 그대로 더한 값입니다. 결과에는 글자 100개당 비용이 `total=88.3  effort=121.4  sfb=17.6  scissors=11.3  rolling=-62.0`처럼 나오며, 낮을수록 좋습니다.
   - 분모는 언제나 글자(a–z) 수입니다. 스페이스를 배열에 두면 스페이스 누름의 비용도 같은 분모로 나눠 총점에 들어가고, 그 몫(스페이스 누름의 노력값과 스페이스가 낀 n-gram의 비용)을 `(space key 21.3 of the total)`처럼 따로 보여 줍니다. 스페이스를 넣은 만큼 총점이 커지므로 엄지 방식의 점수와 바로 비교하지 마세요.
   - 손 비율에는 배열에 있는 키의 누름이 모두 들어갑니다(스페이스를 배열에 두면 스페이스 포함).
   - 기준값은 `[costs]`에서 대표 사건 하나의 비용으로 정합니다: SFB(검지 홈 → 윗줄), 나쁜 방향 풀 시저스(중지 아랫줄 → 검지 윗줄), 안쪽 롤(중지 홈 → 검지 홈), 리다이렉트(홈 행 약지 → 검지 → 중지), 가운데 열로 뻗기(중지 홈 → 가운데 홈). 나머지 사건은 `[weights]`의 세부 배율로 정해집니다.
   - **effort**: 키마다 정한 노력값입니다. 행과 가운데 열에 페널티가 붙습니다.
   - **sfb**: 같은 손가락으로 연속해서 치는 경우(SFB)와, 사이에 한 글자를 두고 같은 손가락으로 치는 경우(스킵그램)의 페널티입니다. 스킵그램은 `[weights]`의 `sfs` 배율(기본 설정 0.5, 없으면 1 = SFB와 같은 무게)을 곱합니다. `ere`처럼 1·3번이 같은 글자인 같은 키 스킵그램은 어느 배열에서나 같은 키라 피할 수 없으므로 `sfs_same_key`(기본 설정 0)로 따로 정합니다. 같은 글자 연속(`ll`)은 SFB로 세지 않습니다. 배율 1일 때 실제 코퍼스에서는 이 항목의 약 3/4이 스킵그램에서 나옵니다. 공백을 사이에 둔 스킵그램(`e_d`처럼 단어 끝과 다음 단어 첫 글자가 같은 손가락)도 같은 배율로 셉니다. 엄지로 공백을 누르는 동안 손가락이 미리 움직일 수 있는 점이 다른 손가락이 끼는 경우와 같기 때문입니다.
   - **rolling**: 같은 손 안에서 바깥에서 안쪽으로 굴러가는 롤에 주는 보너스입니다. 바깥으로 굴러가는 롤은 `outroll` 배율을 곱합니다. 두 키의 노력값 합이 클수록 보너스가 줄고, 행이 한 번 바뀔 때마다 `roll_row` 배율을 곱합니다(리다이렉트는 반대로 행이 바뀌면 그만큼 비싸짐). 같은 손 세 글자가 방향을 꺾는 리다이렉트는 하나의 사건으로 쳐서, 안의 두 쌍은 롤로 치지 않고 `[costs]`의 `redirect` 비용만 매깁니다. 검지가 없는 리다이렉트는 `bad_redirect` 배율을 곱합니다.
   - **scissors**: 인접한 손가락이 서로 다른 행을 칠 때의 페널티입니다. 같은 손에서 가운데 열 키와 다른 손가락 키를 잇따라 치는 "가운데 열로 뻗기(LSB)"도 이 항목에 들어가므로, 가운데 열을 많이 쓰는 배열은 이 숫자가 커집니다. LSB 한 번의 비용은 `[costs]`의 `lateral`(중지 홈 → 가운데 홈)로 정하고, 다른 LSB는 두 키의 노력값 합과 행 이동에 비례합니다(`lateral`이 없으면 예전처럼 노력값 합 × `center` × 행 배율을 시저스 단위로 씀). 가운데 열의 SFB(검지 → 가운데)는 SFB 식에 `center`를 곱해 sfb 항목에 들어갑니다. 결과의 `bigrams` 줄에 LSB 비율을 따로 보여 줍니다.
     - 풀 시저스는 두 줄 차이, 나쁜 방향 하프 시저스는 한 줄 차이에서 긴 손가락이 아래로 가는 경우입니다.
     - 스킵 시저스는 1번과 3번 글자가 시저스를 이루는 경우입니다. 공백을 사이에 둔 경우도 셉니다.

## 사용법

```bash
cargo run --release -- <result_path> analyze     # 코퍼스 분석 → <result_path>/corpus.bin
cargo run --release -- <result_path> optimize    # 최적화 → <result_path>/result.bin (space_key = "grid"면 result-grid.bin)
cargo run --release -- <result_path> run         # analyze + optimize
cargo run --release -- <result_path> results     # 저장된 결과 출력
cargo run --release -- <result_path> score mine.txt   # 내 배열을 저장된 결과 1등과 같은 기준으로 채점
cargo run --release -- <result_path> sensitivity mine.txt   # 점수 설정값에 결과가 얼마나 민감한지 점검
```

- `score`의 배열 파일은 행마다 10칸(빈칸은 `.`)씩 3행입니다. `space_key = "grid"`면 `_`가 스페이스 키이고, 엄지 방식에서는 `_`도 빈칸으로 읽습니다(예전 출력 호환). `results` 출력 형식도 그대로 읽습니다. 점수와 함께 행별 사용률, SFB·스킵그램·롤·시저스·리다이렉트 비율을 보여 줍니다.
  - `windows` 줄은 커뮤니티 분석기처럼 공백까지 넣어 세 키씩 밀며 나눈 창의 비율입니다(엄지 방식이면 공백은 엄지, 배열에 두면 그 자리): 교차, 2키 롤(안쪽·바깥쪽), 세 글자 롤, 리다이렉트, 나쁜 리다이렉트(검지 없음), 같은 손 나머지(SFB·시저스·가운데 열이 낀 창). 스킵그램은 다른 분류와 겹치므로 따로 보여 주고, 그중 공백 너머의 몫을 괄호에 적습니다. 표시용이며 점수에는 위 항목들로 들어갑니다.
- `sensitivity`는 점수 설정값을 하나씩 ±10/20/35/50% 흔들어, 결과가 그 값에 얼마나 기대는지 봅니다. 설정 파일과 결과 파일은 바꾸지 않습니다.
  - 흔드는 값: `[costs]` 6개, `[weights]` 10개(`row`는 SFB·시저스의 행 배율만, `roll_row`는 롤의 행 배율만), `hand_penalty`, 노력값 묶음 5개(새끼·약지·가운데 열·윗줄·아랫줄).
  - 노력값 묶음은 기준 칸보다 큰 부분만 흔듭니다. 열 묶음은 같은 행 검지 대비, 행 묶음은 같은 열 홈 대비입니다.
  - 후보는 저장된 결과 전부와 명령줄에 준 배열 파일입니다. 같은 배열이나 좌우를 뒤집은 배열은 하나만 남깁니다. 지금 설정에서 1등인 후보가 기준입니다.
  - 칸마다 두 가지를 봅니다. 다른 후보가 기준 1등보다 나아지는지, 그리고 바뀐 설정으로 기준 1등에서 근처 탐색(두 키 맞바꾸기·세 키 돌리기를 더 좋아지지 않을 때까지, 무작위 없음)을 했을 때 더 나은 배열이 나오는지입니다.
  - 표의 칸은 `.`(기준보다 나은 배열 없음) 또는 `X0.12`(아래 목록의 배열 X가 기준보다 글자 100개당 0.12 나음)입니다. 둘 다 나으면 더 많이 아끼는 쪽을 보여 줍니다.
  - 표 아래에는 어딘가에서 기준보다 나았던 배열을 모두 보여 줍니다. 배열마다 기준과 자리가 다른 글자와 그 글자들이 타이핑에서 차지하는 비중, 나았던 칸 수와 차이, 해당 설정을 적습니다. 같은 배열이나 좌우를 뒤집은 배열은 하나로 셉니다. 후보 목록에도 후보마다 기준과 다른 글자의 비중을 적습니다.
  - 민감·둔감 같은 분류나 동점 기준은 두지 않습니다. 차이가 작은지, 드문 글자만 바뀌었는지는 수치를 보고 직접 판단합니다.
  - 근처 탐색만 하므로, 후보에 없는 전혀 다른 배열이 1등이 되는 경우는 잡지 못합니다. 그런 게 궁금한 값은 바꿔서 `optimize`를 다시 돌려 보세요.
- `--reset`을 붙이면 기존 결과를 무시하고 새로 시작합니다. 분석 중간 저장(`.partial`)은 덤프·파서·표본 비율이 같으면 `--reset`이어도 이어서 씁니다. 처음부터 다시 하려면 그 파일을 지우세요.
- 예전 버전이 만든 `corpus.bin`은 형식이 달라 읽지 못합니다. `analyze --reset`으로 다시 만드세요. 공백을 세기 전의 코퍼스(파서 v3)는 공백 너머 비용을 계산할 수 없어서, 채점·최적화 명령(`optimize`, `run`, `results`, `score`, `sensitivity`)에서는 거부합니다. 스페이스를 배열에 둘 때는 문장부호 옆 공백까지 세는 파서 v5 이상이 필요합니다. `analyze`로 통계만 볼 때는 읽힙니다. 엄지 방식의 점수는 v4와 v5가 같습니다.
- Ctrl-C를 한 번 누르면 이번 라운드가 끝난 뒤 저장하고 종료합니다. 두 번 누르면 바로 종료합니다.

## 설정 (`config.toml`)

| 항목 | 설명 |
|---|---|
| `space_key` | 스페이스를 어디에 둘지입니다. `"thumb"`(기본)는 엄지 키라 배열 밖이고, `"grid"`는 3×10 배열 안의 27번째 키로 함께 배치합니다(자리 제한 없음). 결과 파일은 따로 저장됩니다(`result.bin` → `result-grid.bin`). |
| `wikipedia_dump_url` | 덤프 주소입니다. 문자열 하나나 목록(공식·미러)으로 적습니다. 목록이면 받기 전에 주소마다 하나씩 차례로 속도를 잽니다. 곳마다 최대 8초 또는 32MiB를 받고, 연결 초반(TCP가 속도를 올리는 구간)을 뺀 뒤쪽 절반의 속도를 씁니다. 첫 데이터가 오기까지의 지연은 속도에 넣지 않습니다. 응답이 없거나 파일 크기가 다른 주소는 빠집니다. 모든 주소는 파일 이름이 같아야 합니다. 병렬 분석과 이어서 분석을 하려면 `*-pages-articles-multistream.xml.bz2`를 쓰세요. |
| `wikipedia_download`, `wikipedia_dump_file` | `wikipedia_download = true`면 덤프를 `result_path` 아래에 먼저 받아 두고, 끊겨도 이어받습니다. 파일 이름은 URL의 마지막 부분입니다. 이름을 직접 정하려면 `wikipedia_dump_file`을 쓰세요. 둘 다 없으면 스트리밍으로 한 스레드에서 분석합니다. 전체 덤프는 약 27GB입니다. |
| `wikipedia_parallel_download` | 여러 미러에서 8MiB 덩어리를 나눠 동시에 받습니다(기본 켜짐). 미러마다 연결은 하나이고, 같은 서버(같은 IP)를 가리키는 여러 주소는 가장 빠른 하나만 씁니다. 가장 빠른 곳의 20% 미만인 미러는 예비로 두었다가, 쓰던 미러가 계속 실패하면 그 연결이 넘겨받습니다. 받을 덩어리가 다 나가면 남은 연결이 가장 오래 걸리고 있는 덩어리를 같이 받아, 끝부분이 느린 미러에 묶이지 않습니다. 받은 덩어리는 `<파일>.part`의 제자리에 쓰고 `<파일>.part.state`에 기록하므로, 중단해도 다시 실행하면 남은 덩어리만 받습니다. 예전 방식으로 받다 만 `.part`도 이어받습니다. 끄면 가장 빠른 한 곳에서 받다가 계속 실패하면 다음 곳으로 넘어갑니다. |
| `wikipedia_verify` | 다 받은 덤프를 Wikimedia가 공개하는 SHA-1(`<wiki>-<날짜>-sha1sums.txt`)과 비교합니다(기본 켜짐). 체크섬은 공식 주소에서 먼저 구합니다. 다르면 파일을 `<이름>.bad`로 옮기고 멈추며, 체크섬 파일을 못 구하면 경고만 하고 진행합니다. |
| `wikipedia_sample` | 문서 표본 비율입니다(0 초과 1 이하). 제목 해시로 덤프 전체에서 고르게 뽑습니다. |
| `wikipedia_limit` | 덤프 앞쪽 N개 문서만 분석합니다(0 = 전체). 오래된 문서 위주라 편향되므로 빠른 확인용입니다. |
| `bigram_coverage`, `trigram_coverage` | 최적화에 쓸 빅그램·트라이그램의 누적 빈도 비율입니다(기본 0.99, 0.97). 글자끼리의 것, 채점에 쓰는 `글자 _ 글자` 창, 나머지 공백이 낀 것에 따로 적용해서, 묶음마다 기준만큼 남습니다. 코퍼스 파일에는 전체 통계를 저장하므로, 바꿔도 다시 분석할 필요가 없습니다. |
| `elites`, `min_home_diff` | 엘리트 배열 수와, 엘리트끼리 홈행 글자가 최소 몇 개 달라야 하는지입니다. |
| `min_hand_usage`, `hand_penalty`, `hand_hard_limit` | 손 비율 제약입니다. 덜 치는 손이 `min_hand_usage` 이상이면 감점이 없고, 모자라면 글자 100개당 `hand_penalty × (모자란 %p)²`를 감점합니다. `hand_hard_limit` 아래는 실격입니다(지정하지 않으면 `min_hand_usage`와 같아서 기준 아래는 바로 실격). |
| `center_rare` | 빈도가 가장 낮은 n글자를 가운데 두 열에 강제로 배치합니다(0 = 끔, 2–6). |
| `seed` | 난수 시드입니다. 비워 두면 실행할 때마다 출력되는 값을 넣어 같은 실행을 재현할 수 있습니다. |
| `[weights]` | 세부 배율입니다. `row`는 SFB·시저스의 행 페널티(한 줄 차이마다 `1 + row`배), `roll_row`는 롤의 행 배율(없으면 `row`와 같음)로 뜻이 다릅니다. 그 밖에 손가락 간격(`gap`), 가운데 열(`center`), 롤 방향(`outroll`), 리다이렉트·시저스·스킵그램 종류별 배율이 있습니다. |
| `[effort]` | 키마다의 노력값입니다(검지 홈 = 1.0). 왼손 새끼부터 가운데 열까지 행마다 5칸이고 오른손은 좌우 대칭입니다. 쓰시는 키보드에 맞게 바꿀 수 있고, 바꿔도 `[costs]`의 대표 사건 비용은 그대로 유지됩니다. |
| `[costs]` | 총점의 기준값입니다. 대표 사건(SFB, 나쁜 방향 풀 시저스, 안쪽 롤, 리다이렉트, 가운데 열로 뻗기) 한 번이 검지 홈 행 키 몇 번을 누르는 만큼인지와 노력값 배율을 정합니다. 예전 설정의 `score_normalization`, `[rates]`는 무시됩니다. |
| `[sa]` | 담금질 한 번의 파라미터(`max_no_improve`, `accept_start`, `cooling`)와 여러 번 시작하기 설정(`starts_per_batch`, `stop_after_hits`, `max_starts`)입니다. 예전 설정의 `[ga]`는 무시됩니다. |

## 테스트

```bash
cargo test
```

### 덤프 파싱 확인 (`test_dump`)

```bash
cargo run --release --bin test_dump -- <result_path> [articles]   # 기본 2000, 0이면 첫 문서만
```

- 첫 본문 문서의 원문과 정리된 결과를 보여 줍니다.
- 앞쪽 `articles`개 문서를 정리해서 아래 내용을 출력합니다.
  - 많이 나온 단어 상위 60개
  - 마크업 찌꺼기로 의심되는 토큰(`nbsp`, `frac`, `jpg`, `http` 등)의 100만 단어당 빈도
  - 끝 섹션(References, See also 등)을 잘라 낸 문서의 비율
- 의심 토큰 가운데 `times`, `minus`처럼 원래 영어 단어인 것은 절대값보다 수정 전후 비교에 쓰세요.
